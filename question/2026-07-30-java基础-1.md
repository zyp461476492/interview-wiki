## Q1：**`String`、`StringBuilder`、`StringBuffer` 三者有什么区别？为什么 Java 要把 `String` 设计成不可变（immutable）的？不可变带来了哪些好处？**

### A：

三者区别：String 本质是一个 char[]，每次初始化完毕后都不可变，如果要调整，则需要进行数组复制等重操作。
StringBuilder 和 StringBuffer 就是可以追加字符，在字符多的时候低成本的修改字符串，这两个区别是 StringBuilder 是线程安全的。
设计不可变，本质是为了方便设计逻辑，也符合字符串本来就是一个类似常量概念。不可变后就不用考虑线程安全，并发等各种问题。

### evaluation

**得分：4 / 12.5**

**问题：**
1. **关键概念错误**：将 StringBuilder 与 StringBuffer 的线程安全性搞反了。正确是：`StringBuilder` **非**线程安全（性能好），`StringBuffer` 线程安全（方法用 `synchronized` 修饰，性能略低）。
2. 不可变好处仅提到"线程安全"，遗漏了：字符串常量池复用、hashCode 缓存（适合做 HashMap key）、安全性（防止敏感数据被篡改）、equals/hashCode 语义稳定。

**参考答案要点：**
- String 不可变（内部 `final char[]`，JDK9+ 为 `byte[]`）；StringBuilder 可变、非线程安全、性能好；StringBuffer 可变、线程安全（synchronized）、性能略低。
- 不可变好处：常量池复用、线程安全、hashCode 缓存、安全性、集合 key 语义稳定。

**改进建议：** 重点记牢三者线程安全的对应关系；不可变好处从"内存复用 / 并发 / 哈希 / 安全"四个维度记忆。

## Q2：**请分别说明 `final`、`finally`、`finalize` 的作用。它们之间有任何关系吗？`finally` 块在哪些情况下不会被执行？**

### A：

final：表示这个变量不可修改，不可变。
finally: try catch 后最终要执行的流程
finalize: java 程序的生命周期

finally 如果之前 try catch 的 catch 里有 reture ，可能不会被执行。

### evaluation

**得分：3 / 12.5**

**问题：**
1. **关键概念错误**：说"catch 里有 return 可能不执行 finally"——**恰恰相反**，try/catch 中 `return` **不会**阻止 finally 执行，finally 会在 return 之前执行。
2. `final` 只提了"变量不可修改"，遗漏修饰类（不可继承）、修饰方法（不可重写）；且对象引用 final 时内容仍可变。
3. `finalize` 描述为"java 程序的生命周期"不准确，应为 `Object` 方法，GC 回收对象前由 JVM 调用（JDK9 已废弃）。

- finally 真正不执行的情况：① `System.exit()` 导致 JVM 退出；② 根本没进入 try 块前就异常/return；③ 线程被杀死；④ try/catch 内无限循环或死锁。
- final：修饰类/方法/变量三方面；finally：异常处理资源关闭；finalize：GC 前调用，已废弃。

**改进建议：** 牢记"return 不阻止 finally"这一高频考点；final 三个修饰维度要答全。

## Q4：**`synchronized` 和 `volatile` 的区别是什么？各自适用于什么场景？请详细说明 `synchronized` 在 JDK 1.6 之后的「锁升级」过程（偏向锁 -> 轻量级锁 -> 重量级锁）。**

### A：

synchronized 是重量级锁，但是在 jdk1.6后，也优化了，根据情况不同会执行不同阶段的锁升级。适合对并发一致性要求高的场景
volatile 是保持线程可见性，基本无性能开销，使用于读一致性要求高，并且性能要求高的场景

synchronized 在 1.6 后，会根据情况进行锁升级

### evaluation

**得分：3 / 12.5**

**问题：**
1. volatile 只提"保持线程可见性"，**遗漏关键点"不保证原子性"**和"禁止指令重排序（有序性）"。
2. synchronized 未点明保证"原子性 + 可见性 + 有序性"三者。
3. **锁升级过程完全未展开**（题目明确要求"详细说明"），仅重复"会根据情况进行锁升级"。

**参考答案要点：**
- 区别：synchronized 互斥锁，保证原子性+可见性+有序性，竞争时阻塞；volatile 保证可见性+有序性，不保证原子性，不阻塞。
- 锁升级（存储在对象头 Mark Word）：无锁 → 偏向锁（记录线程 ID，同线程免 CAS）→ 轻量级锁（CAS 自旋，低竞争）→ 重量级锁（OS monitor，高竞争阻塞）。升级不可逆。
- 适用场景：synchronized 复合操作/临界区；volatile 一写多读状态标志。

**改进建议：** 锁升级四级过程（无锁/偏向/轻量级/重量级）必须能完整复述，这是 synchronized 高频考点。

## Q7：**在项目中需要实现一个「线程安全的单例模式」。请给出至少两种实现方式（如饿汉式、双重检查锁、静态内部类、枚举等），并对比分析它们的优缺点、线程安全性和延迟加载特性。**

### A：

饿汉式
存在问题：并发时，可能判断 obj == null，但实际已经执行到初始化步骤了，导致被初始化两次。
```java
public static class Demo1 {
    private static final Demo1 obj;
    private Demo1() {}

    public static synchronized get() {
        if (obj == null) {
            obj = new Demo1();
        } else {
            return obj;
        }
    }
}
```

双重检查锁
可以解决并发时的问题。
```java
public static class Demo2 {
    private static final Demo2 obj;
    private Demo2() {}

    public static  get() {
        if (obj == null) {
            synchronized {
                if (obj == null) {
                    obj = new Demo1();
                }
            }
        } else {
            return obj;
        }
    }
}
```java

**参考答案要点：**
- JMM：定义多线程共享变量访问规则--每线程有工作内存，共享变量在主内存，线程间通过主内存交互，规定何时刷回/读取。
